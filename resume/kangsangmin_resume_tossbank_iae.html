DevOps 팀에서 PR 검증·회귀·통합 테스트 CI/CD 자동화를 담당했고, 이후 ATD(Application Technology Development) 팀에서 NPU 플랫폼 애플리케이션을 개발했습니다. 재직 중 342건의 이슈·기능 개발을 처리했습니다.

1. 회귀 테스트 자동화 플랫폼 설계·구축·운영

  • 문제 — 약 600개 모델 변형에 대해 컴파일→런타임 2단계 워크플로우를 일 10회 실행해야 했으나, 가용 자원은 컴파일 서버 10대·런타임 서버 12대로 제한. 실행마다 환경 셋업(드라이버, 빌드, 펌웨어 설치)이 반복되어 오버헤드가 병목이었습니다.
  • 해결 — 컴파일 단계는 가상환경(venv)을 서버 간 공유해 반복 환경 구성을 제거하고, 런타임 단계는 드라이버·빌드·펌웨어 버전을 사전 체크해 변경이 있을 때만 재설치하는 조건부 셋업 로직을 설계 — 동일 작업의 무의미한 반복(Toil)을 시스템이 스스로 걸러내도록 구성. CPU 집약적인 컴파일과 디바이스 종속적인 런타임의 자원 특성을 분리해 서버 풀별로 작업을 스케줄링.
  • 성과 — 제한된 자원으로 일 10회 전체 회귀 사이클을 안정 운영. 셋업 오버헤드 제거로 사이클당 실행 시간을 단축하고, 수작업 개입 없이 결과가 축적되는 운영 체계를 확립.

2. CI 파이프라인 최적화 및 마이그레이션 (Jenkins → GitHub Actions)

  • 문제 — 레거시 Jenkins 기반 PR 검증이 복잡하고 중복된 스테이지로 인해 오래 걸리고, 파이프라인 유지보수가 어려웠습니다.
  • 해결 — 빌드·테스트 스테이지를 프로파일링해 중복 단계와 불필요한 순차 실행 구간을 식별. 분석 결과를 기반으로 GitHub Actions로 마이그레이션하며 독립적인 빌드·테스트 잡을 병렬 실행하도록 재설계하고, 워크플로우 구조를 단순화해 팀원 누구나 파이프라인을 읽고 수정할 수 있게 개선.
  • 성과 — 전체 CI 실행 시간 약 40% 단축, 유지보수성·가독성 개선. "느리지만 건드리기 무서운 CI"를 "빠르고 누구나 고칠 수 있는 CI"로 전환.

3. 멀티모델 NPU 스트리밍 애플리케이션 자동 에이징 테스트

  • 문제 — 다수의 YOLO 모델을 NPU에서 동시 실행하는 스트리밍 애플리케이션의 장기 안정성 검증에 사람이 지켜볼 수 없는 48시간 연속 테스트가 필요했습니다.
  • 해결 — 내부 런타임 서비스(dxrt.service)와 IPC로 연동해 추론 워크로드를 연속 실행하는 테스트 프레임워크를 설계. NPU 사용률·디바이스 온도 등 런타임 메트릭을 상시 수집하고 사용률 0% 또는 온도 80°C 초과 시 자동으로 실패를 트리거하는 이상 감지 로직을 구현 — 탐지 기준을 사람의 감이 아닌 시스템 규칙으로 명문화. pytest 기반 48시간 연속 테스트로 전체 검증 파이프라인을 자동화.
  • 성과 — NPU 추론 워크로드의 배포 전 안정성 검증을 무인 자동화하고, 릴리스 신뢰성 검증 기준을 확립.
